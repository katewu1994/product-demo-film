# 实施计划

版本：v0.1 · 日期：2026-11-13 · 状态：待实施的开发计划，未通过运行验证。

本计划面向 Codex。执行规则先读 [AGENTS.md](../AGENTS.md)，需求见 [PRODUCT_REQUIREMENTS.md](PRODUCT_REQUIREMENTS.md)，任务卡见 [TASKS.md](TASKS.md)。文档中的架构和数值是本项目的设计决定；不能把它们写进“已完成”报告。

## 1. 目标与完成边界

第一版交付一个可以在用户 Mac 上运行的独立可视化工作台：导入项目介绍/README、仓库和可运行网址，生成以问题开头的产品介绍；用户修改分镜、讲稿和演示步骤后，工具生成画面、执行真实产品操作、保留产品原声，并用 FFmpeg 导出 120–180 秒的完整视频。

默认 `targetDurationMs=150000`，用户可在 120000–180000 范围选择；另设 `competitionMaxDurationMs=180000` 作为比赛硬上限，不能把两个字段混为一谈。正式计划按目标换算 `totalFrames`，输出与目标差不超过一输出帧，容器/各音视频流尾部不得超过硬上限。不能满足目标时返回 `duration_conflict`，不静默把目标拉长。

五段预算为 problem 15%、impact 10%、solution 15%、proof 50%、value 10%。这是初始模板，不是效果研究结论。真实产品操作和声音的完整性优先于比例。proof 可以包含说明画面、动画和真实演示，不能把整支介绍片缩成录屏。

第一版成功必须同时包含可视化工作台、自动生成链路、真实演示和原声、可修改与局部重做、可复现导出。用手工导入素材拼出的成片可以验证剪辑器，不能证明自动生成链路完成。

## 2. 每个任务都执行的小循环

1. **定位最小目标。** 从任务卡选一个有明确可见结果的子任务，读取相关设计与当前代码；检查是否已有用户授权、配置和前置证据。
2. **写清成功条件。** 在任务记录里写本轮要改变的用户行为、验证方法和预期产物，避免先做通用框架再找用途。
3. **实现可运行增量。** 数据、接口、界面与最小异常处理一起完成；允许用明确标识的 fixture 验证一个模块。
4. **运行相关验证。** 优先执行能够暴露本轮风险的测试，再运行项目规定的必要检查。记录实际命令、退出码、素材来源和结果。
5. **检查用户可见结果。** 打开界面或播放样片；自动检查通过不能替代画面、声音和叙事检查。
6. **修正实现或设计。** 如果证据否定了设计假设，记录决定及原因，再修代码；不能删掉验收条件把失败改成通过。
7. **更新状态并继续。** 更新 [VALIDATION_STATUS.md](VALIDATION_STATUS.md) 和本轮任务记录。在同一已授权范围内继续下一项可执行工作。

任务结束时提供简短的“变化、证据、剩余问题、下一步”。用户可以在任何时候评估结果并修正规则；普通本地实现、测试、修复和已批准步骤的重跑不需要逐项重复确认。需要付费生成时，应先具备有效配置和本次运行预算；已授权预算内不按镜头反复询问。

## 3. 实施顺序与依赖

以下顺序用于尽早暴露不确定性，不代表完成所有设计后才能开始编码。不同工作可以在接口确定后并行；修改同一数据契约时要先协调。

| 任务 | 本轮可见结果 | 必须的前置条件 |
| --- | --- | --- |
| T00 | 环境与模型能力报告，命令入口契约落地 | 阅读交付文档，检查本机现状 |
| T01 | 可创建、保存、重开项目的本地工作台，最小持久化任务队列 | T00 的技术栈决定 |
| T02 | 自动操作有声测试网页并录出带原声的文件 | T00；T01 的最小任务/产物记录 |
| T03 | Codex 分镜图片实际落盘，并经已验证的 Omni 接口生成视频 | T00；T01；实际账号能力与预算 |
| T04 | 确定性时间轴混合素材，输出可核验的预览/导出 | T01；T02 录制素材；允许测试生成素材替身 |
| T05 | 30–45 秒真实混合样片，能改单镜头后局部重做 | T02、T03、T04；真实产品和有效原声场景 |
| T06 | 输入材料转成有来源的产品事实和五段讲稿 | T01；T00 已确认的规划模型接口 |
| T07 | 选择预设风格、审阅和修改图片分镜 | T03、T06；风格与素材契约 |
| T08 | 修改 AI 提出的步骤、排练并执行已批准版本 | T02、T06；演示方案契约 |
| T09 | 讲稿、字幕、产品原声与配音的可控组合 | T04、T06；启用 TTS 时具备真实可用接口 |
| T10 | 根据真实素材重新分配预算，严格控制总时长 | T04、T07、T08、T09 |
| T11 | 把输入、分镜、步骤、预览、局部修改连成完整界面流程 | T06–T10；T05 已验证的集成接口 |
| T12 | 失败、取消、断线和重启后可恢复，缓存不会错误复用 | T01 起逐步建设；完成验收需 T11 |
| T13 | 从真实项目材料产出 120–180 秒完整介绍片 | T05、T11、T12；真实配置和产品材料 |
| T14 | 本机启动、配置、排障和交付步骤可复现 | T13；全部必要验收通过 |

T12 的可靠性基础不应推迟到最后：T01 就持久化任务与产物；T03 在调用付费服务前持久化请求；T04 按不可变计划渲染。T12 负责集中故障注入与收尾，而非首次引入这些机制。

## 4. 验证门槛

### G0：环境与接口边界明确

T00 完成实际环境检查，记录 Codex、Chrome、FFmpeg、Node 与依赖版本；写明哪些模型能力有官方文档依据、哪些只有静态代码依据、哪些已在当前账号运行成功。缺少账号或密钥不等于模型不支持，记为 `blocked` 或 `unverified` 并写明差什么。

G0 不要求先产生所有付费素材，但必须阻止猜测接口、伪造成功结果和静默改用其他模型。

### G1：关键模块分别可运行

T02 证明真实 Chrome 录制得到预期原声并达到同步目标；T03 证明图片实际落盘并传入目标视频生成器；T04 证明时间轴、音频和导出行为可测。模块测试通过只用于对应能力，不能提前宣布整套产品通过。

### G2：短片混合链路通过

T05 产出 `purpose=validation_sample` 的 30–45 秒样片，同时包含实际生成画面、真实目标产品操作、产品原声、标题/字幕，以及独立旁白（若本轮启用）。至少修改一次镜头并证明只重新生产受影响素材。使用 fixture 网页时仅记为“机械链路验证”；未录制真实目标产品，G2 仍未通过。

此门槛用于决定录制、生成与渲染的当前组合是否继续扩展。若失败，先修复发生失败的边界；项目保存、界面、事实提取等独立任务可继续，不应因为单个模型权限阻塞而停止所有工作。

### G3：完整产品验收通过

T13 用真实项目完成 `purpose=final_product` 的五段叙事和 120–180 秒成片，覆盖 [ACCEPTANCE_CRITERIA.md](ACCEPTANCE_CRITERIA.md) 的 AC01–AC14。T14 验证重新启动和交付步骤。只有 G3 通过才可标记第一版可交付。

## 5. 配置缺口与继续工作的规则

| 发现的问题 | 可以继续 | 不可以宣称 |
| --- | --- | --- |
| 未提供真实 README/仓库/网址 | 用标识清楚的示例开发输入、事实结构和 UI | 已理解并验证用户的真实产品 |
| Codex 当前模式不能输出图片文件 | 记录实际失败；完善适配接口和导入流程；查官方支持路径 | 复制别处图片就等于完成 Codex 自动分镜 |
| Omni 账号或目标接口不可用 | 完成录制、时间轴、工作台；保留独立生成任务 | 换用别的模型后仍标记 Omni 已通过 |
| TTS 未配置 | 验证导入旁白或明确关闭旁白的流程 | TTS 自动生成已经实现 |
| 本机无法捕获标签页声音 | 记录浏览器/系统证据；验证另一个已授权采集方案 | 无声录屏成功就是原声验收成功 |
| 外部调用超时且结果未知 | 持久化 `unknown_external_outcome`；按服务支持查询原请求 | 自动发起新付费请求来掩盖不确定结果 |

阻塞报告必须具体到缺失的输入、配置、权限或失败证据，同时列出已经完成和仍可独立执行的工作。不要只说“需要用户确认”而不提供可审阅内容。

## 6. 证据与任务状态

开发任务状态只使用 `not_started`、`in_progress`、`blocked`、`done`；它们与运行时 Job 状态不是同一枚举。当前所有任务初始为 `not_started`。

运行证据存放在配置的本地数据目录下 `reports/<runId>/`，不默认提交原始录屏、账号信息或完整产品数据到 Git。每次报告至少包括任务 ID、代码 revision、工具版本、输入与产物 hash、实际命令和退出码、期望/实测值、失败与残余问题。把必要的脱敏摘要和证据位置登记到 [VALIDATION_STATUS.md](VALIDATION_STATUS.md)。

`pnpm doctor`、`pnpm verify`、`pnpm verify:live` 等是待实现的命令契约，当前文档包不包含可运行的 package.json。具体含义以 [README.md](../README.md) 和 [TESTING.md](TESTING.md) 为准。

## 7. 何时调整计划

仅在新证据影响实现时调整任务。例：当前 Codex 的图片输出路径不支持后台调用、标签页捕获在目标系统不稳定、首尾帧能力与实际视频接口不符。调整时更新 [DECISIONS.md](DECISIONS.md)、受影响设计、任务依赖和验收映射，保留原始失败记录。

不得为了更快完成任务而删除“真实操作”“产品原声”“独立界面”“Codex 图片到 Omni”中的任意一个核心需求。若必须降低范围，先完成可审阅的替代方案并清楚标注与用户需求的差异。
