## T00 — 环境与能力核查

- **目标：** 确认当前机器和账号可用的能力，建立可运行的项目入口。
- **依赖：** 阅读根目录 [AGENTS.md](../AGENTS.md)、[ARCHITECTURE.md](ARCHITECTURE.md)、[PROVIDERS.md](PROVIDERS.md)；不需要先有任何成片。
- **实施：** 检查本机 Node、pnpm、Codex、完整 Chrome、FFmpeg/ffprobe 与必要编码/滤镜；选定并锁定实际可用版本。读取当前官方 API 文档与本机 CLI 帮助，记录所需调用形式、能力缺口和账号配置，不读出或复制认证密钥。落地 `pnpm doctor` 及其他根命令的入口；不存在的功能要返回明确的未实现状态。
- **输出：** 初始工程、锁文件、环境检查报告、能力矩阵、需用户提供的真实材料/配置清单。
- **验证：** 实际运行环境检查；使用已有依赖和缺失依赖两种情况验证错误信息；不把静态文档检查称为成功 API 调用。
- **Done：** 技术栈已锁定；基础环境可支持后续本地开发；未确认能力逐项标注 `unverified/blocked`，没有伪造已通过项。付费探针放在 T03 和相应 TTS 任务，不能因尚未探针而伪标模型支持。

## T01 — 本地工作台与项目持久化

- **目标：** 在独立界面创建项目，关闭服务后可以完整重开。
- **依赖：** T00；[DATA_MODEL.md](DATA_MODEL.md)。
- **实施：** React 页面、Fastify API、SQLite 迁移、项目创建/编辑/读取；默认五段结构、150 秒和风格预设。建立最小 Job 队列、事件、版本、产物元数据和工作目录；数据写入采用事务。每个 UI 操作有加载、失败和恢复状态。
- **输出：** 可打开的本地工作台与可持久化 Project；最小假任务仅测试队列，明确显示测试性质。
- **验证：** 创建两个项目后重启，确认互不串数据；提交旧 revision 更新收到冲突；崩溃前已提交的项目仍存在；默认只绑定本机地址。
- **Done：** 重开项目恢复内容和任务状态；无虚假的进度或素材；实际操作演示和证据记录完成。

## T02 — 真实录制与原声采集验证

- **目标：** 证明当前目标机器能自动操作真实 Chrome 并捕获网页声音。
- **依赖：** T00；T01 的最小 Job/Asset 记录；[CAPTURE_AND_AUDIO.md](CAPTURE_AND_AUDIO.md)。
- **实施：** 建立本地可控测试网页与具有已知 A/V 关系的校准媒体，先核实媒体与测量算法，再验证播放、等待、导航和收音。同一目标标签页的持续 capture stream 中，内部 leader → 产品/测试操作 → 内部 trailer，记录 monotonic 事件与媒体时钟映射。实际产品点击到声音的业务延迟不能当校准标准。要求原声时，缺轨或未采到预期声音直接失败。
- **输出：** 原始录制文件、事件日志、ffprobe 元数据、起末同步偏差报告。
- **验证：** 实际播放与测量；去掉收音权限/音轨、错误浏览器通道、超时、页面关闭等故障不能产生成功标记。默认同步目标为同流首尾校准事件偏差分别不超过 80ms，属于项目验收目标；缺锚点记 av_sync_unverified，正式片不能泄漏校准媒体。
- **Done：** 在主要目标系统通过 fixture 的真实采集，且原声与画面均经核验；fixture 通过不代表用户产品已通过。若采集受阻，状态保持 blocked，写清失败与可替代采集试验。

## T03 — Codex 图片到 Omni 的真实验证

- **目标：** 打通用户指定的生成链路，获得真正可解码的产物。
- **依赖：** T00、T01；配置可用的 Codex 图片路径、目标 Omni 接口、费用预算；[PROVIDERS.md](PROVIDERS.md)。
- **实施：** 让 Codex 发起一次小规模分镜图片任务并将实际图片落盘；验证文件类型、尺寸和 hash；把这份图片作为参考输入目标 Omni 适配器，保存请求、外部 operation ID、状态与最终视频。付费创建前持久化请求指纹，创建结果未知不能盲目重发。
- **输出：** 图片文件、生成视频、请求与响应的脱敏元数据、实际模型标识、能力/成本记录。
- **验证：** 请求确实引用该图片；媒体可以解码；中断查询后可恢复已有任务；返回文字路径但无文件不能成功；更换输入后不能命中旧结果。
- **Done：** Codex 图片到已选 Omni 接口的真实调用完成，来源可追踪。手工导入图片、mock 视频、其他模型或第三方接口替代均必须单独标注，不能直接通过本任务。未配置必要账号/预算时为 blocked，继续独立任务。

## T04 — 确定性时间轴与 FFmpeg 渲染

- **目标：** 用一个不可变计划产生正确的预览和成片。
- **依赖：** T01；T02 的真实采集文件；[TIMELINE_AND_RENDERING.md](TIMELINE_AND_RENDERING.md)。T03 未通过时允许标识为 fixture 的动画素材测试渲染，但不满足 T05。
- **实施：** 素材探测与规范化、整数帧调度、A/V 成对剪切、标题与字幕叠加、转场、独立音轨和最终 FFmpeg 调用。先完成最小可运行路径，再增加必要的效果。预览与导出共用计划，只改变输出质量。
- **输出：** TimelineRevision、渲染计划、预览 MP4、1080p 导出、探测报告。
- **验证：** 30fps 与 24fps 来源混用；带转场的总长计算；无音轨素材；路径含空格；非零起始 PTS；不能触发 shell 拼接执行。检查最终流和容器时长、音轨、分辨率、字幕与转场位置。
- **Done：** 计划匹配 targetDurationMs，结果与目标差不超过一输出帧；容器/各流不超过 competitionMaxDurationMs 硬上限且没有尾包豁免；原声不变速、不丢失，预览与导出内容一致；损坏文件不能被标记 ready。

## T05 — 30–45 秒混合样片

- **目标：** 在扩展完整工作台前验证生成画面、真实操作和原声能组成同一支介绍片。
- **依赖：** T02、T03、T04；真实目标产品网址、可重复演示场景和有效原声；本次生成预算已配置。
- **实施：** 通过最小 UI/API 流程制作一条样片：生成画面、真实目标产品操作、产品声音、标题/字幕，若启用旁白则加入独立配音。修改一个标题或镜头后再次生成，记录实际重跑边界。
- **输出：** purpose=validation_sample 的样片、分镜/步骤批准版本、产物 hash 清单、局部重做对比报告。
- **验证：** 原声存在且语义完整、声音没有被生成音轨替换；该真实 DemoRun 的同流 leader/trailer 证据同步达标，样片排除内部校准/导航段；改标题不会重新调用 Omni 或重录；改生成镜头会使其下游视频/渲染失效，独立录制仍复用。独立 fixture 的成功不能替代真实录制首尾证据。
- **Done：** G2 通过并有真实运行证据。若仅用测试网页或导入生成素材，只能记录“组件联调通过”，任务不能标记完整 done。

## T06 — 材料导入、事实提取与五段讲稿

- **目标：** 从用户已有材料得到可核查的产品介绍初稿。
- **依赖：** T01；规划模型接口已核实且可用；[PRODUCT_REQUIREMENTS.md](PRODUCT_REQUIREMENTS.md)。
- **实施：** 接收文本/README、仓库引用和网页；保存来源 revision/hash。生成 ProductFact 与来源片段，区分已证实、用户提供、待确认；从这些事实生成 problem/impact/solution/proof/value。没有证据的性能数字、客户、功能或收益不进入事实性旁白。
- **输出：** 来源索引、事实表、五段讲稿、初始预算和待确认点。
- **验证：** 相互矛盾的 README 与网页；材料不足；仓库含提示注入；修改一个事实后相关讲稿标记 stale；生成结果必须符合 schema。
- **Done：** 可以从界面审阅事实和来源并修改讲稿；素材内容不能覆盖项目 AGENTS 指令；引用目标真实存在。

## T07 — 风格预设与图片分镜工作台

- **目标：** 不要求用户写创意描述，也能得到统一的视觉初稿。
- **依赖：** T03、T06；[STYLE_GUIDE.md](STYLE_GUIDE.md)、[UI_SPEC.md](UI_SPEC.md)。
- **实施：** 实现默认风格与可选预设、品牌色/标志/字体输入；生成每镜头的用途、画面类型、叙事关系、图片和动作说明。分镜卡允许修改、替换、重新生成；生成画面与真实演示清楚区分。
- **输出：** StylePreset revision、Shot 列表、真实分镜图片与生成任务。
- **验证：** 修改预设只使相关视觉素材失效；保持真实录屏原始内容；拒绝用生成画面冒充产品实际操作；关键文字由后期标题层准确绘制。
- **Done：** 用户仅选择预设/品牌即可生成初稿；修改和局部重做可用；实际图片而非占位图通过 AC06 的相关条件。

## T08 — 演示步骤编辑、排练与正式录制

- **目标：** 实现“AI 提步骤 → 用户修改 → 工具执行已批准版本”。
- **依赖：** T02、T06；[WORKFLOWS.md](WORKFLOWS.md)、[CAPTURE_AND_AUDIO.md](CAPTURE_AND_AUDIO.md)。
- **实施：** 生成 schema 约束的 DemoScenario；显示动作、目标、预期结果、等待、前置状态和音频窗口；保存 approvedRevision。排练测量实际耗时；正式录制只运行匹配的批准版本。局部重录可以重放必要前置步骤而不把它们剪进成片。
- **输出：** 演示步骤编辑器、排练结果、DemoRun、真实录制和事件。
- **验证：** 未批准/已变更步骤不能正式执行；locator 失败、登录过期、媒体播放失败会停在具体步骤；重复执行从可控状态开始；不能执行任意 JS/shell。
- **Done：** 用户能修改步骤并在界面启动一次录制；实际结果经断言核验，原声与事件记录完整；不会绕过需额外授权的外部副作用。

## T09 — 旁白、字幕和音轨安排

- **目标：** 让声音支持产品表达，避免旁白盖住需要听清的产品原声。
- **依赖：** T04、T06；启用 TTS 时目标接口和预算可用；[CAPTURE_AND_AUDIO.md](CAPTURE_AND_AUDIO.md)。
- **实施：** Narration 分段生成/导入、实际时长探测；字幕绑定对应文本及实际音频时间。实现产品原声独占窗口、解释窗口、背景音乐开关和音量。生成视频声音默认关闭，保留必须明确选择并标记来源。
- **输出：** 独立旁白文件、字幕、音轨安排、可听预览。
- **验证：** 讲稿改动使相关旁白和字幕失效；产品原声窗口不会被 TTS/BGM 遮盖；源容器内嵌音轨和 product_audio 引用不会重复混入；不把字符数估计当成精确语音对齐；无音乐配置时不自动填入来源不明音乐。
- **Done：** TTS 模式真实调用通过，或该模式明确 blocked；导入旁白流程通过不等于 TTS 通过。启用的声音模式满足 AC09、AC10。

## T10 — 总时长与段落预算调度

- **目标：** 依据实际素材生成符合目标时长的整片计划。
- **依赖：** T04、T07、T08、T09；[TIMELINE_AND_RENDERING.md](TIMELINE_AND_RENDERING.md)。
- **实施：** 把 targetDurationMs 与 ms 预算转换为整数帧，计算转场重叠，并独立校验 competitionMaxDurationMs；使用真实录制、生成视频和旁白时长。优先缩短重复讲解/可裁等待，再建议删减具体内容；不可通过产品原声变速、循环假操作或截断语义来套比例。无法满足所选目标返回 duration_conflict，不静默放宽到比赛上限。
- **输出：** 验证通过的 TimelineRevision、各段实际时间、必要的删减候选。
- **验证：** 120/150/180 秒边界；分数帧；多转场；实际声音超预算；用户锁定片段已超过总上限时明确返回不可行原因。
- **Done：** 预算可调整但总长不越界；不可能的约束不会强行产出伪合格影片；调度输出稳定且可重现。

## T11 — 完整界面与局部修改

- **目标：** 用户能在一个工作台完成输入、编辑、录制、预览和导出。
- **依赖：** T06–T10；T05 已验证的模块接口；[UI_SPEC.md](UI_SPEC.md)。
- **实施：** 串联各页面，呈现当前 revision、真实状态、失败项、费用/预算与下一步；支持修改一段讲稿、一张分镜、一组步骤、一段声音后局部重做。简化交互，不要求用户操作终端完成日常制作。
- **输出：** 完整可交互工作台；可重开项目和历史产物选择。
- **验证：** 页面刷新/断线后恢复状态；过期素材不可无提示导出；重复点击不会创建重复任务；长任务期间仍可查看既有结果。
- **Done：** 能从界面完成目标用户流程；没有以静态页面或播放按钮代替真实执行；未完成的能力在 UI 明确标识。

## T12 — 可靠性、取消、恢复与缓存

- **目标：** 失败时不丢项目，不错误复用旧素材，不重复产生费用。
- **依赖：** 从 T01 起同步建设；完整验证需要 T11；[DATA_MODEL.md](DATA_MODEL.md)、[PROVIDERS.md](PROVIDERS.md)。
- **实施：** 明确 Job 状态转移、租约、重启恢复、ProviderOperation 查询、取消边界、产物原子提交和依赖失效；限制并发，记录可恢复/不可恢复失败。
- **输出：** 故障处理、恢复界面、局部重做与证据报告。
- **验证：** 在付费创建响应丢失、下载一半、文件写完但数据库未提交、渲染中、取消后晚到结果、租约失效后旧 attempt 返回等边界注入故障。未知结果经对账按显式转移恢复，旧 attempt 不能发布或覆盖新结果。验证缓存键覆盖输入、参数、模型、风格与实现版本；只靠文件存在不得命中。
- **Done：** 状态与真实产物一致；未知外部结果保持 unknown_external_outcome，不盲目重发；取消后不把迟到结果发布为当前成功；恢复流程有实际执行证据。

## T13 — 真实项目完整成片验收

- **目标：** 用真实项目证明第一版实现满足需求。
- **依赖：** T05、T11、T12；真实材料、目标产品、账号和预算；启用 TTS 时 T09 的真实能力通过。
- **实施：** 从空项目开始，经界面完成五段介绍、风格、分镜、步骤修改、生成与录制、声音安排、导出；至少做一次用户修改后重新导出。
- **输出：** purpose=final_product 的 120–180 秒正式片、完整可重开项目、来源/版本/执行记录、AC01–AC14 验收报告。
- **验证：** 自动媒体检查与完整人工观看/收听结合；逐条执行 [ACCEPTANCE_CRITERIA.md](ACCEPTANCE_CRITERIA.md)。记录端到端时间、重试次数、人工干预时间和已知费用，不据单次运行推导普遍节省率。
- **Done：** 所有必须项通过且没有未披露替代；最终视频达到目标精度且不超过 competitionMaxDurationMs；用户看到的内容和操作真实一致。没有真实产品或模型能力时保持 blocked。

## T14 — 本机交付与使用说明

- **目标：** 用户可以按说明启动并再次完成制作。
- **依赖：** T13；所有必要验收通过。
- **实施：** 完成 README 中安装、doctor、启动、配置、演示账号、失败恢复、数据备份、版本升级步骤；提供无密钥示例配置。核对正式启动仅绑定本机。把实际实现与文档差异修正。
- **输出：** 本地可运行版本、锁定依赖、使用文档、已知限制和验证报告索引。
- **验证：** 在隔离工作目录按说明安装/启动，重开已有项目、再次导出；运行 `pnpm verify`，配置允许时执行 `pnpm verify:live`；确认未提交密钥、浏览器登录态和原始私人数据。
- **Done：** 命令与实际行为一致；用户无需猜测步骤；完成状态与证据吻合。未通过的核心项不能藏在“已知限制”中仍标完成。
